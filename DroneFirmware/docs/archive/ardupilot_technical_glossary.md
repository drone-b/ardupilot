# ArduPilot Technical Glossary

## Scope

This document is a practical glossary of drone, flight-control, and realtime/embedded-software terms
that appear frequently across the ArduPilot codebase and its surrounding tooling.
It was compiled from a repository scan of vehicle code, shared libraries, HAL layers, logging,
telemetry, and autotest infrastructure, then rewritten in original form for `DroneFirmware`.

It is intentionally engineering-focused rather than academic. The goal is to make the vocabulary used
in ArduPilot easier to map into the evolving proprietary `DroneFirmware` architecture.

Representative source areas scanned:

- `ArduCopter/`
- `ArduPlane/`
- `Rover/`
- `ArduSub/`
- `libraries/AP_*`
- `libraries/AC_*`
- `libraries/AP_HAL*`
- `libraries/GCS_MAVLink/`
- `Tools/autotest/`

## 1. Vehicle and Mission Terms

| Term | Meaning |
|---|---|
| Airframe | Physical vehicle type or geometry, such as quadcopter, plane, rover, or submarine. |
| Multirotor | Rotorcraft with multiple propellers providing lift and control. |
| VTOL | Vertical Takeoff and Landing vehicle, often combining multirotor and fixed-wing behavior. |
| Quadplane | Hybrid vehicle that flies as both a plane and a multirotor. |
| Tailsitter | VTOL airframe that rests on its tail and transitions between vertical and forward flight. |
| Tiltrotor | Vehicle whose motors or rotors tilt to transition between hover and forward flight. |
| Frame | Vehicle motor/servo geometry and its mapping to control axes. |
| X configuration | Common quadcopter layout with arms arranged diagonally relative to the front. |
| Plus configuration | Layout where one motor is aligned with the front axis. |
| Mission | Stored set of commands, waypoints, and actions executed autonomously. |
| Waypoint | Target position or navigation point inside a mission. |
| Home | Reference position used for return logic, safety actions, and relative navigation. |
| Rally point | Predefined safe return/diversion location. |
| Geofence | Spatial boundary used to constrain the vehicle or trigger safety behavior. |
| Terrain following | Altitude or clearance control relative to ground shape rather than sea-level altitude. |
| Reposition | Command that changes the active navigation target during operation. |
| Dead reckoning | Position propagation based on internal motion estimates when external references are degraded. |
| Loiter | Mode that holds position or circles around a location. |
| RTL | Return to Launch or Return to Home behavior. |
| Guided | Mode where an external system provides targets or commands. |
| Auto | Fully mission-driven mode. |
| Stabilize | Pilot-assisted attitude-stabilized mode. |
| Acro | Rate-control mode that gives the pilot direct angular-rate authority. |
| AltHold | Mode that stabilizes altitude while leaving horizontal motion partly manual. |
| PosHold | Mode that stabilizes both position and attitude with pilot override. |
| SmartRTL | Return mode that uses a remembered path rather than only a straight-line return. |
| QHover / QLoiter / QRTL | Quadplane-specific VTOL modes. |

## 2. Attitude, Motion, and Control Terms

| Term | Meaning |
|---|---|
| Attitude | Vehicle orientation in space. |
| Roll | Rotation around the longitudinal axis. |
| Pitch | Rotation around the lateral axis. |
| Yaw | Rotation around the vertical axis. |
| Body frame | Coordinate frame attached to the vehicle. |
| Earth frame / navigation frame | External reference frame used for navigation and position control. |
| Rate loop | Inner control loop regulating angular rates. |
| Attitude loop | Outer control loop regulating roll/pitch/yaw angles or attitude targets. |
| Position loop | Control loop regulating position and velocity. |
| Cascaded control | Nested loop structure where outer loops generate targets for inner loops. |
| Setpoint / target | Desired command value for a controller. |
| Error | Difference between target and measured state. |
| PID | Proportional-integral-derivative controller. |
| PI | Proportional-integral controller without derivative term. |
| P term | Immediate response proportional to current error. |
| I term | Accumulated response used to cancel steady-state bias. |
| D term | Predictive damping based on rate of change. |
| Anti-windup | Logic preventing integrator growth when the actuator/controller is saturated. |
| Saturation | Condition where output hits its allowed limit. |
| Unsaturated output | Raw controller output before clamping. |
| Saturated output | Final controller output after limits are applied. |
| Derivative on measurement | Derivative computed from measured rate rather than error, reducing setpoint kick. |
| Mixer | Allocation logic mapping axis/thrust demands into actuator commands. |
| Allocation | Distribution of control authority across motors or servos. |
| Thrust | Force generated by propulsion that contributes to lift or forward motion. |
| Torque | Rotational effect used to change angular state. |
| Yaw headroom | Remaining actuator margin available for yaw control after roll/pitch/throttle demands. |
| Thrust linearization | Compensation that accounts for nonlinear motor/propeller response. |
| Feedforward | Controller component based on commanded motion rather than feedback error. |
| Slew rate | Limit on how fast a command or output may change. |
| Command model | Mapping from pilot or guidance commands into physically achievable targets. |
| Autotune | In-flight or assisted gain-tuning process. |
| Angle assist | Logic that stabilizes or limits attitude even when the pilot is giving manual input. |

## 3. Estimation and Navigation Terms

| Term | Meaning |
|---|---|
| AHRS | Attitude and Heading Reference System, producing orientation estimates. |
| EKF | Extended Kalman Filter, used for state estimation from multiple sensors. |
| State estimator | Software that fuses measurements into attitude, velocity, position, and bias estimates. |
| Sensor fusion | Combining multiple sensor sources into a more robust estimate. |
| Bias | Slowly varying offset in a sensor or state estimate. |
| Gyro bias | Estimated offset in angular-rate sensing. |
| Drift | Slow cumulative deviation, often from inertial integration. |
| INS | Inertial Navigation System. |
| IMU | Inertial Measurement Unit containing gyros and accelerometers. |
| Delta angle | Integrated gyro rotation over a sample interval. |
| Delta velocity | Integrated acceleration over a sample interval. |
| Innovation | Residual between predicted and measured value inside a filter. |
| Fusion source | Sensor or input selected as part of the estimator. |
| Mag fusion | Use of magnetometer data in heading estimation. |
| Air data fusion | Use of airspeed/barometric data in state estimation. |
| Optical flow fusion | Use of image motion estimates for velocity/position aiding. |
| Range beacon fusion | Use of ranging infrastructure in localization. |
| Origin | Reference location used by the navigation solution. |
| Climb rate | Vertical speed estimate. |
| Velocity estimate | Estimated linear motion in one or more axes. |
| Position estimate | Estimated location in a global or local frame. |
| Complementary filter | Lightweight estimator blending fast gyro integration with slower absolute references. |
| DCM | Direction Cosine Matrix representation and associated attitude-estimation approach. |
| Vicon / Visual Odom | External motion-capture or vision-based pose source. |

## 4. Sensor Terms

| Term | Meaning |
|---|---|
| Accelerometer | Sensor measuring specific force or acceleration. |
| Gyroscope / gyro | Sensor measuring angular rate. |
| Magnetometer / compass | Sensor measuring magnetic field for heading estimation. |
| Barometer | Pressure sensor used for altitude estimation. |
| GNSS | Global Navigation Satellite System. |
| GPS | Global Positioning System, often used generically for GNSS. |
| Airspeed sensor | Sensor estimating flow speed relative to air. |
| Optical flow | Sensor/data source measuring apparent ground motion from imagery. |
| Rangefinder | Sensor measuring distance to a nearby surface. |
| LiDAR | Laser-based ranging sensor. |
| Sonar | Acoustic range sensor, often used for close surface distance. |
| Surface tracking | Maintaining distance to a surface using a range sensor. |
| Temperature compensation | Correcting sensor output using measured temperature. |
| Calibration | Estimating offsets, scales, or alignments for sensors. |
| Consistency check | Cross-check between redundant sensors. |
| Health flag | Indicator that a sensor is behaving within acceptable limits. |
| Data-ready interrupt | Hardware signal indicating a sensor sample is ready. |
| Sample period | Time between measurements. |
| Sample age | Time elapsed since a measurement was taken. |
| Transport latency | Time between physical measurement and software acquisition. |
| Glitch | Short, suspicious measurement anomaly. |
| Vibration | Mechanical noise that corrupts inertial sensing. |
| Harmonic notch filter | Narrowband filter targeting motor/rotor vibration harmonics. |

## 5. Actuation and Propulsion Terms

| Term | Meaning |
|---|---|
| Motor output | Command sent to an electric motor channel. |
| Servo output | Command sent to a servo actuator. |
| ESC | Electronic Speed Controller for brushless motor control. |
| PWM | Pulse-width modulation output. |
| DShot | Digital motor-control protocol for ESCs. |
| OneShot | Faster analog-style ESC protocol. |
| RCOutput | HAL layer responsible for low-level actuator signal generation. |
| Interlock | Safety gate that controls whether propulsion may run. |
| Spool-up / run-up | Controlled acceleration of motors/rotor to operating speed. |
| Throttle | Pilot or controller demand for propulsion effort. |
| Spin arm / spin min | Configured motor spin states when armed but not yet commanding flight thrust. |
| Reverse thrust | Negative-propulsion behavior used mainly in some plane/rover contexts. |
| Vectoring | Redirecting thrust mechanically rather than only by motor torque differential. |
| Motor loss handling | Logic coping with reduced control authority after actuator failure. |
| Rudder differential thrust | Using asymmetric motor thrust to contribute to yaw control. |

## 6. Safety, Arming, and Fault Terms

| Term | Meaning |
|---|---|
| Arming | Transition that authorizes propulsion/control outputs. |
| Disarm | Transition that removes propulsion authority. |
| Arming check | Validation run before allowing arming. |
| Pre-arm check | Health/configuration check performed before arming. |
| Failsafe | Protective response triggered by fault or loss of required inputs. |
| GCS failsafe | Safety action triggered by loss of ground-station link. |
| RC failsafe | Safety action triggered by radio-control loss. |
| Battery failsafe | Safety action triggered by low battery or power fault. |
| Sensor failsafe | Safety action triggered by invalid sensor state. |
| EKF failsafe | Safety action triggered by estimator instability or invalidity. |
| Watchdog | Hardware/software mechanism detecting stalled execution. |
| Crash check | Logic attempting to detect impact or uncontrollable state. |
| Land detector | Logic estimating whether the vehicle is landed. |
| Fence breach | Condition where a geofence has been violated. |
| Emergency stop | Immediate propulsion shutdown behavior. |
| Standby | Non-flying but initialized state used in some platforms. |
| Health monitor | Supervisory logic observing subsystem validity. |
| Latch | Safety behavior that remains active until explicitly cleared. |

## 7. Communications and External Interface Terms

| Term | Meaning |
|---|---|
| Telemetry | Runtime data sent off-board for monitoring or control. |
| MAVLink | Common message protocol used by ArduPilot for telemetry, commands, and missions. |
| GCS | Ground Control Station. |
| Companion computer | Onboard higher-level computer communicating with the flight controller. |
| UART | Serial communication interface. |
| SPI | High-speed synchronous peripheral bus. |
| I2C | Two-wire peripheral bus often used for sensors. |
| CAN | Controller Area Network bus. |
| UAVCAN / DroneCAN | CAN-based protocol family for drone peripherals. |
| Serial manager | Layer that assigns serial ports to telemetry, GPS, RC, etc. |
| Payload space / tx space | Remaining room in a telemetry transmit path. |
| Framed protocol | Byte stream organized into sync, length, checksum, and payload. |
| CRC | Cyclic redundancy check used for corruption detection. |
| Routing | Forwarding messages between ports or systems. |
| Parameter download/upload | Ground-station exchange of configuration values. |
| Mission upload | Transfer of waypoints and autonomous commands to the vehicle. |
| FTP over MAVLink | File transfer performed through the MAVLink transport. |

## 8. Realtime and Embedded Software Terms

| Term | Meaning |
|---|---|
| HAL | Hardware Abstraction Layer. |
| Scheduler | Runtime component deciding which tasks execute and when. |
| Cyclic executive | Cooperative loop that runs scheduled jobs in fixed order. |
| Task budget | Maximum intended execution time for a scheduled task. |
| Deadline miss | Case where work was not completed by its intended release/deadline window. |
| Overrun | Execution time exceeding the configured budget. |
| Slack | Spare time remaining before a higher-priority task must run. |
| Fixed priority | Scheduling policy with static task importance levels. |
| Cooperative scheduling | Model where tasks run until they return; no forced preemption. |
| Preemption | Interrupting a running task so another task can execute. |
| ISR | Interrupt Service Routine. |
| DMA | Direct Memory Access engine used to move data without CPU copying. |
| FIFO | First-In, First-Out buffer, common in UART/SPI drivers. |
| Ring buffer | Circular buffer used for bounded streaming I/O. |
| Bounded execution | Guarantee that a call or task finishes within a known time limit. |
| Enqueue-only write | Non-blocking driver API that accepts data for later transmission and returns immediately. |
| Blocking call | Function that waits for hardware completion or resource availability. |
| Jitter | Variation in execution timing or sample timing. |
| Release-based scheduling | Scheduling using absolute next-release timestamps rather than delay chaining. |
| Backlog catch-up | Executing delayed jobs in succession to “catch up,” often harmful in control firmware. |
| Heap allocation | Dynamic memory allocation at runtime. |
| Static allocation | Memory fixed at compile/startup time. |
| Determinism | Predictable timing and behavior for the same input and state. |
| RTOS | Real-Time Operating System. |
| Thread | Independently scheduled execution context. |
| Semaphore | Synchronization primitive for shared resources or signaling. |
| Lock / mutex | Mutual exclusion mechanism protecting shared state. |
| Timestamp | Monotonic time mark attached to an event or sample. |
| Monotonic clock | Clock that never moves backward. |
| Startup hook / init | Initialization phase before flight logic begins. |

| Term | Meaning |
|---|---|

| HIL | Hardware In The Loop testing. |
| Autotest | Automated integration test framework used by ArduPilot. |

## 10. ArduPilot-Specific Naming Patterns Worth Recognizing

| Pattern | Meaning |
|---|---|
| `AP_*` | General ArduPilot shared library prefix. |
| `AC_*` | Commonly Copter-centric control libraries. |
| `AR_*` | Rover-specific libraries. |
| `GCS_*` | Ground-control and MAVLink communication layers. |
| `AP_HAL_*` | Hardware-specific HAL implementations. |
| `SITL` | Simulation backend modules and test harnesses. |
| `mode_*` | Vehicle-mode implementations. |
| `Parameters.*` | Static parameter declarations and storage mapping. |
| `Log.*` or `LogStructure.*` | Logging schema or message writers. |

## 11. Mapping Guidance for DroneFirmware

These ArduPilot terms map naturally into the current `DroneFirmware` design:

- `AP_HAL` -> `platform/`
- `AP_Scheduler` -> `runtime/`
- `AP_InertialSensor` -> `sensing/`
- `AP_AHRS` / `EKF` layers -> `estimation/`
- `AC_AttitudeControl` / rate control -> `control/`
- `AP_Motors` -> `control/` + actuator allocation/output path
- `AP_Param` -> `config/`
- `GCS_MAVLink` / telemetry -> `comms/`
- `AP_Logger` -> `logging/`
- arming/failsafe logic -> `safety/`

- This document focuses on the vocabulary that is most relevant to architecture, control, telemetry,
  safety, estimation, and realtime execution.
